# Implementation Report: CR-009 Reporting and Analytics Endpoints

## 1. Document Control & Metadata
- **Change Request ID:** CR-009
- **Title:** Reporting and Analytics Endpoints
- **Priority:** Medium
- **Difficulty:** Intermediate Change
- **Type:** Backend reporting, SQL aggregation, and dashboard modernization
- **Target Application:** Course Management System (CMS) / Student Management System
- **Date:** October 2026
- **Status:** Completed & Verified

---

## 2. Business Requirement & Objective
Administrators need accurate reports about courses, students, and enrollments across the entire institution. Students need an immediate, isolated summary of their personal learning progress and activity.

### Previous Behaviour
- The Admin Dashboard and Student Dashboard previously fetched unaggregated raw data (such as calling `/courses/stats`, `/enrollments`, or `/enrollments/my`) and attempted to compute counts, distinct sets, and sums on the client-side using JavaScript `Array.reduce` and `Set` operations.
- This approach caused:
  1. Excessive network payload transfer.
  2. Inaccurate counts when server-side pagination was introduced (e.g., counting only the 20 records returned on page 1).
  3. High client-side compute overhead.
  4. Potential `NaN` and runtime crashes when values were null or empty.

### Requested Change
- Implement efficient, role-specific server-side reporting endpoints using native SQL aggregations (`COUNT`, `SUM`, `MIN`, `MAX`, `DISTINCT`, `GROUP BY`, `DATE_SUB`).
- Update the Admin Dashboard and Student Dashboard to consume these reporting endpoints.
- Ensure strict access control, complete data isolation between students, zero N+1 query loops, and full protection against `NaN` or dashboard crashes.

---

## 3. Scope & Architecture

### 3.1 Backend Endpoints
1. **Admin Overview Report:** `GET /api/reports/overview`
   - Restricted exclusively to authenticated administrators (`admin` role).
   - Computes 8 system-wide metrics via SQL aggregation:
     1. Total courses
     2. Total students
     3. Total enrollments
     4. Number of students with enrollments (`COUNT(DISTINCT student_id)`)
     5. Enrollments during the last 30 days (`enrolled_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)`)
     6. Enrollments by category (`GROUP BY c.category`)
     7. Top five courses by enrollment count (sorted descending by enrollment count, then title)
     8. Number of courses with no enrollments (`LEFT JOIN ... WHERE e.id IS NULL`)
     - *Bonus:* 6 most recent enrollments for dashboard display without extra network requests.

2. **Student Personal Report:** `GET /api/reports/my`
   - Restricted exclusively to authenticated students (`student` role).
   - Scoped strictly to `req.user.id` extracted from verified JWT:
     1. Number of enrolled courses
     2. Number of distinct categories
     3. Earliest enrollment date
     4. Latest enrollment date
     5. Recent enrollment details (course title, category, level, duration, enrolled date, price)
     - *Bonus:* Total enrolled course value, student-specific category breakdown, and total available catalog courses.

### 3.2 Database Indexes & Migration
- Created migration `backend/migration_cr009.sql`:
  - `idx_users_role` on `users(role)`: Accelerates filtering for `role = 'student'`.
  - `idx_courses_category` on `courses(category)`: Accelerates `GROUP BY c.category` aggregation.
- Updated baseline `backend/schema.sql` to include both indexes.

### 3.3 Consideration for CR-011 (Pending Enrollments)
- *Specification Requirement 13:* In the current baseline schema, all records in the `enrollments` table represent active enrollments. If CR-011 introduces an enrollment `status` column (e.g. `'pending'`, `'approved'`, `'rejected'`), all reporting queries should be updated to filter by `status = 'approved'` (or provide an explicit status breakdown), ensuring that unconfirmed/pending applications do not distort active enrollment counts.

### 4.3 `backend/models/reportModel.js` (New File)
Encapsulates all SQL aggregation queries without any N+1 query loops.
- `getAdminOverview()`: Executes parallel aggregate queries using `Promise.all`:
  - `coursesCount`: `SELECT COUNT(*) AS total_courses FROM courses`
  - `studentsCount`: `SELECT COUNT(*) AS total_students FROM users WHERE role = 'student'`
  - `enrollmentsCount`: `SELECT COUNT(*) AS total_enrollments FROM enrollments`
  - `activeStudentsCount`: `SELECT COUNT(DISTINCT student_id) AS students_with_enrollments FROM enrollments`
  - `last30DaysCount`: `SELECT COUNT(*) AS enrollments_last_30_days FROM enrollments WHERE enrolled_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)`
  - `noEnrollmentCoursesCount`: `SELECT COUNT(*) AS courses_with_no_enrollments FROM courses c LEFT JOIN enrollments e ON c.id = e.course_id WHERE e.id IS NULL`
  - `categoryBreakdown`: `SELECT c.category, COUNT(e.id) AS enrollment_count FROM courses c LEFT JOIN enrollments e ON c.id = e.course_id GROUP BY c.category ORDER BY enrollment_count DESC, c.category ASC`
  - `topCourses`: `SELECT c.id, c.title, c.category, c.level, COUNT(e.id) AS enrollment_count FROM courses c LEFT JOIN enrollments e ON c.id = e.course_id GROUP BY c.id, c.title, c.category, c.level ORDER BY enrollment_count DESC, c.title ASC LIMIT 5`
  - `recentEnrollments`: Up to 6 most recent enrollments for admin dashboard preview.
- `getStudentReport(studentId)`:
  - Aggregate metrics query: `COUNT(e.id)`, `COUNT(DISTINCT c.category)`, `MIN(e.enrolled_at)`, `MAX(e.enrolled_at)`, `COALESCE(SUM(c.price), 0)` filtered by `WHERE e.student_id = ?`.
  - Recent enrollments query: Retrieves up to 5 recent enrollments for the student.
  - Student category breakdown: `GROUP BY c.category` for the student's courses.

### 4.4 `backend/controllers/reportController.js` (New File)
- `getAdminOverview`: Verifies `req.user?.role === "admin"`, returning `HTTP 403` if unauthorized, and calls `Report.getAdminOverview()`.

- Handles exceptions gracefully and returns `HTTP 500` with clean error messages.
