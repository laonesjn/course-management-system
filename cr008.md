# Implementation Report: CR-008 Server-Side Search, Filtering and Pagination for Admin Enrollments

## 1. Document Control & Metadata
- **Change Request ID:** CR-008
- **Title:** Server-Side Search, Filtering and Pagination for Admin Enrollments
- **Priority:** Medium
- **Difficulty:** Intermediate Change
- **Type:** Backend and Frontend Performance & Data Management Enhancement
- **Target Application:** Course Management System (CMS) / Student Management System
- **Date:** October 2026
- **Status:** Completed & Verified

---

## 2. Executive Summary & Business Objective
Prior to this change request, the administrative enrollment management interface retrieved all enrollment records from the database in a single unpaginated query. Client-side pagination and filtering were either nonexistent or inefficient, placing unnecessary memory and compute burden on both the database server and the client browser. In addition, there was no comprehensive search by student name/username, date-range filtering, or server-side multi-column sorting.

**CR-008** migrates enrollment retrieval, searching, filtering, sorting, and pagination entirely to the server-side. The database now returns strictly the records needed for the active page, calculates accurate pagination metadata through an isolated `COUNT(*)` query, protects query execution using strict parameterization and wildcard escaping, and provides a modern, responsive user interface with full pagination controls (First, Previous, Next, Last) and state preservation.

---

## 3. Scope & Impact Analysis

### In-Scope
1. **Endpoint Enhancement:** Enhancing `GET /api/enrollments` to support query parameters: `q`, `courseId`, `from`, `to`, `sort`, `order`, `page`, and `limit`.
2. **Input Validation:** Strict backend validation of all query parameters before database query execution, rejecting malformed inputs with **HTTP 400**.
3. **Database Performance & Migration:** Adding database indexes on `enrollments(enrolled_at)`, `enrollments(course_id, enrolled_at)`, `users(full_name)`, and `courses(title)` via a new migration file `backend/migration_cr008.sql` and updating `backend/schema.sql`.
4. **Security & Data Integrity:**
   - Preventing SQL injection via prepared statements (`mysql2`).
   - Safely escaping wildcard characters (`%`, `_`, `\`) in student search.
   - Enforcing an allowlist for sort fields (`enrolled_at`, `student`, `course`) and orders (`asc`, `desc`).
   - Enforcing a stable secondary sort (`e.id`).
   - Restricting `GET /api/enrollments` exclusively to authenticated administrators (`HTTP 403` for students).
5. **Frontend User Interface:**
   - Overhauling `frontend/src/pages/ManageEnrollments.jsx` with search input, course dropdown, date pickers, sorting controls, and page size selection.
   - Adding First, Previous, Next, and Last pagination controls with boundary disable states.
   - Displaying result range strings (e.g. `Showing 1–20 of 137`, `Showing 0–0 of 0`).
   - Automatically resetting page to `1` when filters change.
   - Seamlessly handling deletions: navigating to the preceding page if deleting the last record on an active page empties it, while preserving all active filter criteria.
6. **Dashboard Integration:** Updating `frontend/src/pages/AdminDashboard.jsx` to consume `pagination.total` for the "Total Enrollments" statistic.

### Out-of-Scope / Non-Goals
- Modifying student-facing endpoints (`GET /api/enrollments/my`, `POST /api/enrollments`, `DELETE /api/enrollments/my/:id`).
- Client-side pagination fallbacks.
- Modifying course catalog business logic.

## 4. API Specification: `GET /api/enrollments`

### 4.1 Authentication & Authorization
- **Headers:** `Authorization: Bearer <JWT>`
- **Role Requirement:** `admin` (Students receive `403 Forbidden`).

### 4.2 Query Parameters

| Parameter | Type | Required | Default | Validation Rules & Error Conditions |
| :--- | :--- | :---: | :---: | :--- |
| `q` | String | No | `null` | Searches `users.full_name` OR `users.username`. Wildcard characters (`%`, `_`, `\`) are escaped. |
| `courseId`| Integer | No | `null` | Must be a positive integer $> 0$. Non-numeric or $\le 0$ returns `HTTP 400`. |
| `from` | Date String | No | `null` | Supported formats: `YYYY-MM-DD` or valid ISO/datetime string. Calendar validity verified (`HTTP 400` if invalid). Time boundary defaults to `00:00:00`. |
| `to` | Date String | No | `null` | Supported formats: `YYYY-MM-DD` or valid ISO/datetime string. Calendar validity verified (`HTTP 400` if invalid). Time boundary defaults to `23:59:59`. |
| `sort` | String | No | `enrolled_at` | Allowlisted values: `enrolled_at`, `date`, `enrollment date`, `enrollment_date`, `student`, `student name`, `student_name`, `name`, `full_name`, `course`, `course name`, `course_name`, `course title`, `course_title`, `title`. Unsupported values return `HTTP 400`. |
| `order` | String | No | `desc` | Supported values: `asc`, `desc` (case-insensitive). Unsupported values return `HTTP 400`. |
| `page` | Integer | No | `1` | Must be a positive integer $\ge 1$. Values $< 1$, non-integers, floats, or malformed strings return `HTTP 400`. |
| `limit` | Integer | No | `20` | Must be an integer between `1` and `100`. Values $< 1$, $> 100$, floats, or malformed strings return `HTTP 400`. |

### 4.3 Validation Error Rules
- If `from` is chronologically later than `to`, the API rejects the request with **HTTP 400**: `"Invalid date range: 'from' date cannot be later than 'to' date."`.
- If search or filters match zero records, the API returns **HTTP 200** with `enrollments: []`, `pagination: { page, limit, total: 0, totalPages: 0 }` (never `HTTP 404`).
- If an out-of-range page is requested (e.g. `page=9999` when `totalPages=5`), the API returns **HTTP 200** with `enrollments: []` and accurate pagination metadata (never `HTTP 404`).

### 5.3 Model: `backend/models/enrollmentModel.js`
Added the `getAllPaginated` method to encapsulate SQL query construction:
1. **Wildcard Escaping:** Replaces `%`, `_`, and `\` with `\%`, `\_`, and `\\`.
2. **Parameterized WHERE Clause:** Dynamically accumulates conditions for `q` (`u.full_name LIKE ? ESCAPE '\\' OR u.username LIKE ? ESCAPE '\\'`), `courseId` (`e.course_id = ?`), `from` (`e.enrolled_at >= ?`), and `to` (`e.enrolled_at <= ?`).
3. **Separate COUNT Query:** Executes `SELECT COUNT(*) AS total FROM enrollments e JOIN users u ... JOIN courses c ... ${whereSql}` using identical filtering parameters.
4. **Data Query with Pagination:** Selects required fields with `ORDER BY ${validSortCol} ${validSortDir}, e.id ${validSortDir} LIMIT ? OFFSET ?`.
```javascript
  // Get enrollments with server-side search, filtering, sorting, and pagination
  async getAllPaginated({
    q = null,
    courseId = null,
    from = null,
    to = null,
    sortColumn = "e.enrolled_at",
    sortDirection = "DESC",
    page = 1,
    limit = 20,
  }) {
    const whereClauses = [];
    const params = [];

    if (q) {
      const escapedQ = q.replace(/[%_\\]/g, "\\$&");
      whereClauses.push(
        "(u.full_name LIKE ? ESCAPE '\\\\' OR u.username LIKE ? ESCAPE '\\\\')"
      );
      params.push(`%${escapedQ}%`, `%${escapedQ}%`);
    }

    if (courseId) {
      whereClauses.push("e.course_id = ?");
      params.push(courseId);
    }

    if (from) {
      whereClauses.push("e.enrolled_at >= ?");
      params.push(from);
    }

    if (to) {
      whereClauses.push("e.enrolled_at <= ?");
      params.push(to);
    }

    const whereSql =
      whereClauses.length > 0 ? `WHERE ${whereClauses.join(" AND ")}` : "";

    // 1. Separate COUNT(*) query with the exact same criteria
    const countSql = `
      SELECT COUNT(*) AS total
      FROM enrollments e
      JOIN users u ON e.student_id = u.id
      JOIN courses c ON e.course_id = c.id
      ${whereSql}
    `;

    const [countRows] = await db.execute(countSql, params);
    const total = Number(countRows[0]?.total || 0);

    // 2. Data retrieval query with pagination and stable secondary sort (e.id)
    const offset = (page - 1) * limit;

    const ALLOWED_COLUMNS = {
      "e.enrolled_at": "e.enrolled_at",
      "u.full_name": "u.full_name",
      "c.title": "c.title",
    };
    const validSortCol = ALLOWED_COLUMNS[sortColumn] || "e.enrolled_at";
    const validSortDir = sortDirection.toUpperCase() === "ASC" ? "ASC" : "DESC";

    const dataSql = `
      SELECT
        e.id,
        e.enrolled_at,
        u.id AS student_id,
        u.username,
        u.full_name,
        c.id AS course_id,
        c.title,
        c.category,
        c.level
      FROM enrollments e
      JOIN users u ON e.student_id = u.id
      JOIN courses c ON e.course_id = c.id
      ${whereSql}
      ORDER BY ${validSortCol} ${validSortDir}, e.id ${validSortDir}
      LIMIT ? OFFSET ?
    `;

    const [enrollments] = await db.execute(dataSql, [...params, limit, offset]);

    return {
      enrollments,
      total,
    };
  }
```

### 5.4 Controller: `backend/controllers/enrollmentController.js`
Replaced the simplistic `getAllEnrollments` implementation with a robust controller incorporating:
1. **Administrator Authorization Verification:**
   ```javascript
   if (req.user?.role !== "admin") {
     return res.status(403).json({ message: "Access denied. Insufficient permissions." });
   }
   ```
2. **Date Parser & Validator (`parseDateBoundary`):**
   - Strictly validates `YYYY-MM-DD` calendar limits (days per month, leap years).
   - Assigns start of day (`00:00:00`) to `from` and end of day (`23:59:59`) to `to`.
   - Validates that `from` is not later than `to`.
3. **Allowlist Mapping (`SORT_ALLOWLIST`):**
   Maps friendly query values (`date`, `student`, `course`) to qualified SQL column identifiers.
4. **Integer Sanitization:** Validates `page` ($\ge 1$), `limit` ($1 \le limit \le 100$), and `courseId`.
5. **Metadata Calculation:** Computes `totalPages = total === 0 ? 0 : Math.ceil(total / parsedLimit)`.

### 5.5 Frontend: `frontend/src/pages/ManageEnrollments.jsx`
Complete rewrite to implement server-side controls and interactive state management:
1. **Search & Filter Controls:**
   - Text input for student full name and username.
   - Dropdown for course selection.
   - Date inputs for `from` and `to`.
   - Select dropdowns for sorting field (`Enrollment Date`, `Student Name`, `Course Name`) and direction (`Descending`, `Ascending`).
   - Page size dropdown (`10`, `20`, `50`, `100` per page).
   - "Reset Filters" button to restore default state.
2. **Pagination Buttons:**
   - First (`id="btn-first-page"`): Navigates to page `1`. Disabled when on page 1 or empty.
   - Previous (`id="btn-prev-page"`): Navigates to `page - 1`. Disabled when on page 1 or empty.
   - Next (`id="btn-next-page"`): Navigates to `page + 1`. Disabled when on last page or empty.
   - Last (`id="btn-last-page"`): Navigates to `totalPages`. Disabled when on last page or empty.
3. **Range & Metadata Display:**
   - `Showing 1–20 of 137` / `Showing 0–0 of 0`.
   - `Page X of Y (Z total records)`.
4. **Page Reset on Filter Change:**
   Every filter handler resets `page` to `1` automatically.
5. **Deletion & Page Correction:**
   - Preserves active search, filter, and sort state upon deletion.
   - When the administrator deletes the last remaining item on page $N$ ($N > 1$), automatically decrements the active page to $N - 1$.
   - Empty state cleanly displayed when no records match.
